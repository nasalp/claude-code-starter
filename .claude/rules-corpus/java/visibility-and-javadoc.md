# Visibility Sacred: Package-Private Default, Javadoc Every Public Surface

## Priority

| Priority | Meaning |
|---|---|
| **CRITICAL** | Blocks deployment, no exceptions |

## Rule

**Every type and method in `src/main` is package-private by default.** `public`/`protected` only when caller in different package legitimately needs it. Widening visibility → public surface MUST carry Javadoc justifying existence — what it does, why public, what callers rely on, what changes break contract.

Public not natural state. It's a *contract*. Every public name freezes boundary shape, locks internals into consumer compile graph, obligates package to honour shape across versions. Healthy module: mostly package-private; public surface = narrow waist.

## What is required

### 1. Default visibility is package-private

```java
// ✅ Default form for new types in src/main
class OrderingService {
    void process(Order o) { ... }
}

// ✅ Default form for new methods on a public type
public interface OrderingService {
    void process(Order o);  // interface method — public by definition
}

class DefaultOrderingService implements OrderingService {
    @Override
    public void process(Order o) { ... }   // public because @Override

    Order load(OrderId id) { ... }          // package-private — internal
}

// ❌ Forbidden by default — needs Javadoc justification
public class OrderingService {
    public void process(Order o) { ... }
}
```

### 2. Public only for genuine cross-package surface

`public` type allowed only if at least one holds:

- **Cross-package consumer in `src/main`.** Another package (typically another feature module) imports it.
- **Spring Boot / framework forces it.** `@SpringBootApplication` main, `@ControllerAdvice` global handlers when project convention requires. Each instance documented in Javadoc.
- **Java forces it.** `Throwable` subclasses (rethrown across package boundaries), `interface`/`record`/`enum`/`@interface` (inherently API-shaped). Same Javadoc requirement.

None hold → demote to package-private. Spring auto-wires by interface type; `@Component`/`@Service`/`@Repository`/`@Configuration` work as package-private classes.

### 3. Every public type MUST have class-level Javadoc

Javadoc MUST answer:

1. **What** type does — one to three sentences, business-level.
2. **Why public** — cross-package consumer. Name consumer package if known.
3. **What callers can rely on** — invariants, thread-safety, null contract.
4. **Breaking changes** — adding methods? Fine. Removing? Breaking. Parameter type change? Breaking. Return semantics change? Breaking. Be explicit.

```java
/**
 * Snapshot of an order's lifecycle state, as observed at a point in time.
 *
 * <p>Public because the {@code reporting} and {@code billing} features
 * read order snapshots through the {@link OrderSnapshotReader} port. Both
 * consumers depend on this record's shape; renaming or removing fields is
 * a breaking change for them.
 *
 * <p>Immutable. Safe to share across threads.
 *
 * <p><b>Breaking changes:</b> removing any field, changing any field type
 * to a narrower type, or renaming a field. Adding a new field is
 * non-breaking when the record's canonical constructor remains
 * backwards-compatible (default value on the new field).
 */
public record OrderSnapshot(OrderId id, OrderStatus status, Instant observedAt) {}
```

### 4. Every public method on public type MUST have method-level Javadoc

Javadoc MUST answer:

1. **What** method does (one sentence, no implementation detail).
2. **Each parameter** (`@param`).
3. **Return value** (`@return`) — when `null`, when empty.
4. **Each thrown exception** (`@throws`) and trigger condition.
5. **Side effects** — DB write? Event emit? Lock? State mutation?

```java
/**
 * Returns the most recent snapshot for the given order.
 *
 * @param orderId the order to load, never null
 * @return the snapshot, or {@link Optional#empty()} if the order does
 *     not exist OR has been archived
 * @throws OrderAccessDeniedException if the calling principal does not
 *     have read access to {@code orderId}'s tenant
 */
Optional<OrderSnapshot> latestFor(OrderId orderId);
```

Method-level Javadoc NOT required on:

- `@Override` methods documented on super-type (IDE inherits parent Javadoc).
- Trivial accessors auto-generated by `record`.
- `equals`, `hashCode`, `toString` overrides with no behavioural surprise.

### 5. `protected` treated as public for Javadoc

`protected` extends compile-time surface to subclasses in different packages. Same rules: every `protected` member needs Javadoc.

## What is forbidden

| Pattern | Why |
|---|---|
| `public class Foo {}` with no class-level Javadoc | Public modifier is claim; Javadoc is receipt |
| `public Bar method()` on public type with no method-level Javadoc | Callers have no contract |
| Widening to `public` because same-package test caller needs it | Use `@VisibleForTesting`-style package-private access in tests |
| Widening to `public` "just in case someone needs it later" | YAGNI applies to visibility; widen when cross-package consumer appears |
| Auto-generating `// TODO: javadoc` placeholders | Placeholder worse than none — lies about documented contract |
| Javadoc paraphrasing method name (`/** Process the order. */ void processOrder()`) | Restating signature ≠ Javadoc; noise |

## Enforcement

Three layers:

1. **Checkstyle** — fail build on any `public` type/method in `src/main` lacking class/method Javadoc. `JavadocType` + `JavadocMethod`, `scope=public`.
2. **ArchUnit** — fail build on any `public class` in `src/main` outside documented carve-out (interfaces, records, enums, exceptions, framework-required mains). Project carve-outs in each project's `no-public-classes.md`.
3. **Code review** — reject new `public class` whose Javadoc does NOT name cross-package consumer.
